# KataDroid Android 手机界面

直接打开 `index.html`，无需依赖或联网。设计基准为 **412 × 915 dp Android 竖屏手机**；桌面展示手机画布，手机占满实际视口。

## 布局

棋盘、棋谱控制和当前分析面板始终同屏，不滚动整页。屏幕最底部仅保留「胜率走势 / 变化树」两个分析 Tab。已移除对弈、分析、棋谱、设置四项导航；设置位于右上角三点菜单内。

## 静态状态稿

- `index.html`：胜率走势，整合黑棋胜率、目数差和曲线。
- `tree.html`：完整棋谱树的局部视野。多个历史步骤可以分叉，分支继续产生子分支；高亮当前路径及第 68 手，树在画布之外延续。带全树缩略图、缩放和定位当前控件。
- `variation-b.html`：长按 B 后的预览状态。棋盘标出 Q10 → R10 → P10 的 1–3 手，胜率面板显示该分支的胜率、目数差和虚线预测。退出预览恢复主线。
- `menu.html`：右上角三点菜单展开状态，内含设置入口。

## 后续原生交互约定

变化树是独立的大画布，局部拖动平移、双指缩放，不滚动棋盘或整个页面。节点选择同步棋盘与当前路径；定位当前回到当前节点。树中包含整份训练棋谱的历史与递归变化，并非当前步的候选列表。实际实现需按视野绘制大量节点。

长按棋盘候选点进入变化预览并切到胜率 Tab，保留原主线状态，支持退出。推荐分支不另设常驻列表。

纯 HTML/CSS 和 SVG。两个 Tab 用页面链接方便审阅，三点菜单使用原生 details 展开。未实现树平移缩放、节点选择、长按、设置页、实际对弈或 KataGo 接入，数据均为静态示例。

Chromium 已检查 412×915、375×812、360×740、360×640 和桌面画布，分析面板无纵向溢出。

## KataGo 引擎开关与缓存分析

顶部开关控制计算，不控制分析结果的可见性。用户可以在每个局面计算少量访问（示例为 500 visits）后暂停引擎以节省电量，继续查看已有分析。此处不承诺固定访问数达到任何棋力或准确率。

- `engine-off.html`：引擎暂停后保留第 68 手的胜率、目数差、曲线和棋盘候选点；明确标注「已保存分析 · 第 68 手」「500 visits · 引擎已暂停」。仅通过顶部引擎开关恢复计算，不额外展示底部提示或恢复按钮；保留分析结果。
- `tree-off.html`：保持已有变化树。切换两个分析 Tab 不恢复计算。
- `index.html`：引擎开启状态。静态开/关状态稿沿用相同分析数值和访问数。
- 状态切换使用页面导航，不启动真实引擎。

原生实现：关闭应停止推理、释放计算资源，但保留按局面缓存的分析。新落子或切换到其他节点后，没有缓存就不把旧候选点画在新棋盘上；可保留历史曲线，并明确标注最后已分析手数和当前局面未分析。返回已有分析的节点时直接显示缓存。引擎暂停期间 AI 对手不自动应手。

恢复时保持已保存分析可见，同时显示「启动中／更新中」；结果就绪后替换对应局面的缓存。启动失败时仍保留旧分析并提供重试入口。
